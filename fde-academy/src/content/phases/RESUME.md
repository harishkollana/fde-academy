## Python and Pyodide playground facts (checked in the real browser; explain them to the learner, do not rediscover)
- **Pyodide 0.29.5 = Python 3.13.2; the local validator is Python 3.12, so avoid 3.13-only syntax.** All playgrounds share ONE interpreter and ONE namespace per page: logging handlers, `sys.path` changes and imports persist (use `root.handlers[:] = [...]`, `propagate = False`, clean up in `finally`).
- **Packages that load:** pandas 2.3.3, numpy 2.2.5, pyarrow 22.0.0, fastparquet, xlrd, scipy, matplotlib, lxml, jinja2, pytz, sqlalchemy, pydantic 2.12, pyyaml, `dateutil`, `zoneinfo` only after `import tzdata`. **Do NOT load:** openpyxl, xlsxwriter, tabulate, numexpr, duckdb, polars, rapidfuzz, pandera, pytest, psycopg, requests (show these in fenced code or `local` callouts; the validator rejects them in runnable blocks). Use `difflib` for fuzzy matching. When a lesson needs Excel files in the browser, read a raw grid (`pd.DataFrame(rows)` is what `read_excel(header=None)` returns; `read_csv` is NOT a faithful stand-in because it skips blank lines).
- **App fix in `src/lib/py.js` `runPy`:** when the code imports pandas, `pyarrow` is loaded too (otherwise Parquet and `ArrowDtype` break for the rest of the page session if an earlier playground ran pandas first; pyarrow is a 9.6 MB one-time download). Playgrounds need no `import pyarrow`. The validator venv needs `pyarrow` too (`CLAUDE.md`, `docs/TASKS.md`).
- **Works:** `asyncio.run` (several times per page), `asyncio.timeout`, `TaskGroup`, `except*`, `logging`, `argparse` (raises SystemExit), `tomllib`, `cProfile`/`pstats`, `tracemalloc`, `timeit`, `unittest` and `unittest.mock`, `tempfile`, `pathlib`, `zipfile`, `pickle`, `ast`, `dis`, `heapq`, `bisect`, `difflib`, `pdb` driven by a script (`pdb.Pdb(stdin=StringIO(commands), stdout=...)`; `break` needs a real file in a temp dir), `importlib.metadata` on a dist-info folder on `sys.path`, writing and reading files in the in-memory file system. **Fails or missing:** threads, `ThreadPoolExecutor`, `multiprocessing`, `subprocess`, `sqlite3`, `ssl`, `venv`, `pip`, `hashlib.scrypt` and `pbkdf2_hmac`.
- **Gotchas:** `time.sleep` inside an asyncio task does NOT block other tasks in the browser (a "blocking the loop" demo needs a busy loop); the browser clock is coarse (`timeit` with tiny numbers returned 0: use big `number`s and guard divisions); `ipaddress.ip_address("224.0.0.1").is_global` is True on 3.13; Python 3.13 changes some messages (`json` errors, argparse "choose from"): do not print or quote them; from Python 3.12 `sum()` of floats is compensated (ten 0.10s give 1.0), so float-money demos add in a plain loop or use `0.1 + 0.2`; a raw `sys.exit(3)` or argparse usage error makes `runPy` return `ok: false` with `SystemExit` in the output and one uncaught `pageerror` in the console (harmless; catch `SystemExit` where you demonstrate argparse); `np.arange` and similar default to int32 in the browser (set dtypes explicitly when comparing them); `sort_values` and `nlargest` give no promised order among ties, so add a tie-breaker key in lessons and challenges; do not print the ₹ sign from Python code that the local validator runs (Windows pipe encoding): use `Rs.` in printed text and ₹ only in prose.

## Writing rules learned
- **Sketch rules:** a box's `sub` text may have at most **2 lines** (3 lines overlap the label whatever the box height); an arrow label needs about 110 px of arrow length or it collides with the shapes (draw the label as a separate `text` next to the arrow); table cells do not wrap (size `colW` from the longest cell, mono 13 px is 7.8 px per character, bold mono headers about 8.4); a table `title` is centred over the table and clips if it is longer than the table; arrows should not cross table cells or end on text; keep `text` items with `Z` or `*` in `font: 'mono'` (the Kalam hand font draws a capital **Z like a 2**; boxes and brace labels cannot take a font: draw the box without a label and add a `text`); multiple spaces collapse in SVG text; about 6.5–7.5 px per character at size 14 in `note`/`box` text. ALWAYS screenshot (`shots.mjs`): the validator cannot see overlaps.
- **Markdown renderer:** a table cell cannot contain `|` (not even escaped): write `X | None` in prose. Do not wrap text with `*` in `**bold**`. `prompt`/`note`/quiz/callout text is inline-only where noted (no lists, no `~~`): the validator tells you.
- **Quiz balance:** target answers at A/B/C/D = 1/2/2/1. Edit option order with the Edit tool (PowerShell quoting of backticks fails) and re-check that `a` still points at the correct option. `quiz-balance.mjs` only complains at 4+ of one letter and its `--fix` rotates options (scrambles ascending number lists), so plan positions yourself. READ every marked answer; run the code that a question quotes.
- **Challenges:** a `pychallenge` starter must FAIL the tests and the solution must pass; a test that must see an exception uses a flag (`raised = False; try: ...; except X: raised = True; assert raised`), never `raise SystemExit` inside `try`; compute expected values by running the code, do not guess them. The SQL validator rejects a solution that contains a semicolon (even inside a string) and an `ordered: true` challenge without ORDER BY.
- **Numbers:** every number quoted in a lesson is verified by running the playground (compare with the `note:`). Re-read claims for overstatement; say "check the current page" for tool facts that can change.
- **PowerShell traps:** `Set-Content -Encoding utf8` writes a BOM (breaks `.py` files fed to `pylab.mjs` and is risky for `.js`): use `[IO.File]::WriteAllText(path, text, (New-Object System.Text.UTF8Encoding($false)))` or the Write tool; a backtick inside a double-quoted PowerShell string is an escape character (to edit text with markdown backticks use the Edit tool); stderr of native commands shows as a red NativeCommandError block (the exit code is what matters); `cd` persists between calls, so always `Set-Location` explicitly.
- Lesson order matters: do not use a concept before its lesson without one line of explanation.

## Playground and engine facts for SQL (verified; explain them to the learner, do not rediscover)
- The app sends a whole playground script with `db.exec` as ONE simple-query message. Everything after a COMMIT/ROLLBACK is a new implicit transaction, a later `BEGIN` only warns, a later `ROLLBACK` can undo earlier DDL/inserts of that script, and `SET LOCAL ROLE` / `SET LOCAL` last until the end of that implicit transaction, so after a DO block that does `SET LOCAL ROLE x` the next statement still runs as x unless you `RESET ROLE`. End every transaction demo with an explicit COMMIT/ROLLBACK; put `BEGIN` first in the script. `VACUUM` cannot run inside a script of several statements.
- A failing statement stops the script. To record several errors in one run use a `DO` block with nested `BEGIN … EXCEPTION WHEN OTHERS THEN INSERT … SQLERRM … END`.
- PGlite = PostgreSQL 18.3: MERGE (with `NOT MATCHED BY SOURCE`, `RETURNING merge_action()`), `RETURNING old./new.`, ON CONFLICT, savepoints, FOR UPDATE SKIP LOCKED, advisory locks, `pg_locks`, plpgsql/procedures/triggers/DO/PREPARE, roles/GRANT/SET ROLE/RLS/SECURITY DEFINER, xml (`query_to_xml`, `xpath`) all work. NOT available: extensions (only plpgsql listed), `pg_stat_statements`; `pg_stat_user_tables` counters stay 0; **`statement_timeout` does not fire** (single thread), so show timeouts in `local` callouts for a real server; `COPY … TO '/dev/blob'` runs but shows nothing and `COPY FROM STDIN` is not possible.
- The app shows only the date part of timestamps (`src/lib/db.js` clean()) and stringifies JSON objects: use `::text` / `TO_CHAR`. A raw `timestamp` result (for example `date + INTERVAL '1 month'`) shows ONE DAY EARLY for viewers in India, so always cast it to `::date` or format it with `TO_CHAR`; plain `date` columns are fine. Session time zone follows the viewer's browser: use `SET TIME ZONE` / `AT TIME ZONE` explicitly and never quote the default `TimeZone`.
- SQL challenges must be ONE read-only SELECT/WITH, so DML/DDL/security challenges are "preview" queries over a `WITH … VALUES` block. `setup` on a playground runs hidden before the starter. Avoid unbounded recursive CTEs in playgrounds.
- Role/RLS probes that worked: a role needs `USAGE` on schema, table or column `SELECT`, and `USAGE` on a sequence to insert into a serial table; `COUNT(*)` works with only column grants; `current_setting('app.x', true)` returns NULL when unset (policy fails closed); owner/superuser bypass RLS.
