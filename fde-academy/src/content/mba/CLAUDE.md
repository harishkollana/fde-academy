## Rules
- **Data lives only in `sem1.js`.** Pages read it, so a date, mark or module title is changed in one place. Keep it pure data.
- **Facts come from the official documents, never from memory.** Calendar dates, the assessment scheme, module titles and the start page of each module are copied from the PDFs listed below. Do not guess a date, mark or rule; if the PDFs do not say it, ask Harish. Keep the "dates are subject to change, check AMIGO" note (`CALENDAR_NOTE`).
- **Dates are `yyyy-mm-dd` strings written in local (India) time.** The pages compare strings and use `localKey()` for "today". Do not use `new Date().toISOString().slice(0, 10)` for "today" here: in India it gives the previous day between midnight and 05:30. (The FDE store does use it; that is fine for XP, not for deadlines.)
- **Lessons are the numbered items on each book's contents page** (e.g. `2.4.2 Depreciation – Straight Line Method`). Shape: `module.sections[] = { no: '2.4', title, lessons: [{ no: '2.4.2', title, page }] }`. Titles are copied as the book prints them, quirks included (do not "fix" `Baumoul’s`, `BCG matrix`). `page` is the printed book page the lesson starts on, found by searching the body text and checked against the page number printed on that page. Offset from PDF page: 7 for four of the books, 9 for Marketing Management. Known quirks in the books: Marketing Management Module 4 is titled "Environmental Law, Legislations and Treaties" on its contents page but teaches pricing and channels; and in Marketing Management Module 1 the body numbers 1.8.3–1.8.5 differently from the contents page (the contents page wins, pages were matched by title). The `no` is the lesson's id inside a subject (checked unique) and is used in the lesson URL. A lesson is a link to its page everywhere; the tick box next to it (sidebar and Subject page) only shows whether it is done and is never clickable. Completing happens on the lesson page.
- **Module N is tied to `milestone-N`.** The `Subject` page shows each module's due date by looking up the calendar event with id `milestone-<module number>`. Keep `milestone-1` … `milestone-5` in module order; `milestone-6` is Assignment 2 (the case study) and belongs to no module. A subject with a different number of modules would need that lookup changed.
- **The source PDFs stay outside the repo** (`D:\Ed\MBA\1st Sem`). The app only links to them in words. `D:\Ed` also holds personal documents (ID cards, certificates): never read, copy or publish them.
- **Saved progress** lives in `src/lib/mbaStore.js` (key `mba-acca-progress-v1`, the small `useSyncExternalStore` pattern copied from `src/lib/cmStore.js`). `done` maps `lessonKey(subjectId, lesson.no)` to the local date the lesson was marked complete; `quiz` maps the same key to the best `{ score, total }`. Lesson numbers repeat across subjects (every book has a 1.1.1), so always build the key with `lessonKey`. Never reuse the FDE `useProgress`. If more trackers are added (assignments), add new fields to this same store and keep `load()` tolerant of older saves. The site Settings page and the top bar read this store: if its saved shape changes, change `KEYS`/the import code in `Settings.jsx` and `mbaTopBar.js` too.
- **Completing a lesson** (`LessonBody` in `MbaAcca.jsx`): the button is disabled until the quiz has been answered once (`quiz[key]` exists, any score); a lesson with no written content has no quiz and can be completed at once; undo is always allowed. Harish asked for this flow ("end of lesson quiz, answer, mark lesson complete"). The sidebar and Subject page never complete a lesson.
- **Lesson content (key points and quiz).** One file per module, default export `{ '<lesson no>': { p: [key points], q: [[question, [options], index of the right option, why], …] } }`. Rules: write from the study book, never from memory; put it in your own words and do not copy the book's sentences or its end-of-module questions; 2 to 6 key points (plain text, they are shown as text and searched by the top bar) and 2 to 4 questions per lesson, usually 3; give 3 to 5 options and a one-sentence reason for the right one; no "all of the above"; for numbers, take the figures from the book and recompute them. A book's contents-page lesson can be thin (a heading, a case, a table): write what is actually there and leave out what is not. The options are shuffled by `lessons/index.js` with a seed per question, so write them in any order. **Keep the shape `contentOf()` returns (`{ points, quiz: [{ q, o, a, why }] }`): the top bar reads it.** A lesson with no entry still opens, shows "not written yet" and can be completed.
- **Semester 2** will need a `sem2.js` of the same shape and pages that stop importing `sem1.js` directly. Decide the URL layout with Harish first.
- Reuse the shared look (`page narrow`, `card pad`, `h2`, `callout tip`, `mdtable`, `plainlist`); new classes get the `mc-` prefix. No FDE writing rules apply here (no Kollana Tech data, no validator).

## Writing lesson content (how the 324 existing lessons were made)
The scripts in `scripts/mba-slice/` need Python with PyMuPDF (`pymupdf`) and the PDFs in `D:\Ed\MBA\1st Sem`. Pick an output folder **outside the repo** (the book text is not to be committed), then, from that folder's path as `OUT`:
1. `python -I scripts/mba-slice/extract.py OUT` → `OUT/afm.txt, me.txt, mm.txt, pc.txt, sfm.txt` (text of each book, with `=====PDFPAGE n=====` markers).
2. `python -I scripts/mba-slice/parse_toc.py OUT` → `OUT/toc.json` (modules, sections, lessons from each contents page).
3. `python -I scripts/mba-slice/find_pages2.py OUT` → `OUT/toc_pages2.json` (adds the printed start page of each lesson).
4. `python -I scripts/mba-slice/slice.py OUT` → `OUT/mod_<book>_<module>.txt`, one block per lesson, boilerplate and number-only table lines removed, each lesson cut at 3,600 characters and the last lesson of a module cut at its "Summary". Read one file, write that module's `mN.js`.
Book keys: `afm` Accounting, `me` Economics, `mm` Marketing, `pc` Communication, `sfm` Statistics. The scripts cut text by the headings in the book body; a few lessons are matched by title because the body numbers them differently (see the quirks in `RESUME.md`). If a slice looks misaligned (a lesson's text is another lesson's), fix the matcher before writing.

It must say "0 problem(s)". It also prints how the right answer is spread over A to D (it should be roughly even).
- Run `npm run build`, then `npm run dev` and open `/mba-acca`, `/mba-acca/assessment`, `/mba-acca/subjects/accounting-for-managers` and one lesson (for example `/mba-acca/subjects/accounting-for-managers/lessons/1.1.2`) at 1280 px and at 390 px wide; the console must stay clean. On the lesson page check that the complete button is disabled until the quiz is answered, and that the sidebar tick turns green afterwards.
- Lesson counts per subject must stay 78, 89, 128, 57 and 97 (449). Every lesson `no` must start with its section's `no`, which must start with its module's number.
