## Playground and engine facts (verified; explain them to the learner, do not rediscover)
- The app sends a whole playground script with `db.exec` as ONE simple-query message. Everything after a COMMIT/ROLLBACK is a new implicit transaction, a later `BEGIN` only warns, a later `ROLLBACK` can undo earlier DDL/inserts of that script, and `SET LOCAL ROLE` / `SET LOCAL` last until the end of that implicit transaction, so after a DO block that does `SET LOCAL ROLE x` the next statement still runs as x unless you `RESET ROLE` (this broke two playgrounds in `sql-roles-security`). End every transaction demo with an explicit COMMIT/ROLLBACK; put `BEGIN` first in the script. `VACUUM` cannot run inside a script of several statements.
- A failing statement stops the script. To record several errors in one run use a `DO` block with nested `BEGIN … EXCEPTION WHEN OTHERS THEN INSERT … SQLERRM … END`.
- PGlite = PostgreSQL 18.3: MERGE (with `NOT MATCHED BY SOURCE`, `RETURNING merge_action()`), `RETURNING old./new.`, ON CONFLICT, savepoints, FOR UPDATE SKIP LOCKED, advisory locks, `pg_locks`, plpgsql/procedures/triggers/DO/PREPARE, roles/GRANT/SET ROLE/RLS/SECURITY DEFINER, xml (`query_to_xml`, `xpath`) all work. NOT available: extensions (only plpgsql listed), `pg_stat_statements`; `pg_stat_user_tables` counters stay 0; **`statement_timeout` does not fire** (single thread: `pg_sleep(2)` finishes under a 100 ms timeout), so show timeouts in `local` callouts for a real server; `COPY … TO '/dev/blob'` runs but shows nothing and `COPY FROM STDIN` is not possible, so CSV loading is taught with `local` callouts plus a hand-written CSV-field function.
- The app shows only the date part of timestamps (`src/lib/db.js` clean()) and stringifies JSON objects: use `::text` / `TO_CHAR`. A raw `timestamp` result (for example `date + INTERVAL '1 month'`) shows ONE DAY EARLY for viewers in India, so always cast it to `::date` or format it with `TO_CHAR`; plain `date` columns are fine. Session time zone follows the viewer's browser: use `SET TIME ZONE` / `AT TIME ZONE` explicitly and never quote the default `TimeZone`.
- Challenges must be ONE read-only SELECT/WITH, so DML/DDL/security challenges are "preview" queries over a `WITH … VALUES` block. Shared JS constants generate both a playground `setup` SQL and the challenge CTEs (used in several T04 lessons). `setup` on a playground runs hidden before the starter.
- Role/RLS probes that worked (used in `sql-roles-security`): a role needs `USAGE` on schema, table or column `SELECT`, and `USAGE` on a sequence to insert into a serial table; `COUNT(*)` works with only column grants; `current_setting('app.x', true)` returns NULL when unset (policy fails closed); owner/superuser bypass RLS.

## Rules learned (do not repeat)
- The local validator cannot catch browser-only failures (Pyodide has no `hashlib.pbkdf2_hmac`, threads, `multiprocessing`, `socket`, `ssl`, `sqlite3`). Run the crawl before calling a phase done.
- No prices, salaries, weeks or time estimates. Never state tool versions or quotas as facts without "check the current page". No legal claims about data-protection law.
- `prompt`/`note`/quiz/callout text is inline-only where noted (no lists, no `~~`) — the validator tells you.
- Keep this RESUME.md and `docs/TASKS.md` current after each step.
