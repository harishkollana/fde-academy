# Stage 9 · AI engineering (six separate phases)

Prerequisites: `python`, `fastapi`, `foundations`, `sql` (for text-to-SQL), `docker`. Closes with **Project F + Gate F**. Line format: `- [✅] \`lesson-id\` Title — covers`.

**Rules for this whole stage.**
- Never state model names, prices, context sizes or rate limits as facts: use placeholders ("MODEL_SMALL", "check the current page").
- Every lab keeps cost tiny (small datasets, a hard monthly spend limit set first).
- Browser simulators (TokenCost, RagSearch, ToolCallDemo, GuardrailTester, EvalRunner) are deterministic and teach the mechanics without a real model.

## Phase 29 · `llm-basics` — LLM fundamentals and prompting · ★ core · 6 lessons

**Why companies need it.** You cannot debug or cost an AI feature without a working mental model of tokens, context and sampling.
**Concept-first.** A model predicts the next token from a context window; everything else is engineering around that.

- `llm-basics-how-models-work` How LLMs work — transformer intuition, tokens, embeddings, attention in plain words, pre-training vs fine-tuning vs RLHF
- `llm-basics-tokens-context-cost` Tokens, context windows, cost and latency — counting, truncation, price = tokens × rate (placeholder rates), time-to-first-token; TokenCost
- `llm-basics-prompting` Prompting — system vs user messages, few-shot, step-by-step reasoning, prompt patterns, delimiters, prompt-injection intro
- `llm-basics-model-selection` Choosing a model — open vs hosted, size vs quality vs latency vs cost, benchmarks and their limits, local models for privacy
- `llm-basics-limits-hallucination` Limits and hallucination — why models are confidently wrong, temperature, determinism, when not to use an LLM
- `llm-basics-lab` Lab: prompt by hand — extract invoice fields in a chat playground, compare prompts, record what breaks

**Interview questions:** What is a token? · What does temperature do? · Context window limits and what you do about them · Fine-tuning vs RAG vs prompting · Why do models hallucinate?

## Phase 30 · `llm-apis` — LLM APIs, structured outputs and tool calling · ★ core · 7 lessons

**Concept-first.** An API call is a function from messages to a message; structure and tools turn text into software.
**Setup.** A provider API key (direct) and/or Azure OpenAI via Azure (deployments, endpoints, Entra or key auth). Pay-per-use: set a limit first.

- `llm-apis-providers` Direct provider API vs Azure OpenAI — endpoints, deployments, keys vs Entra auth, content filters, quotas, region/data-residency questions
- `llm-apis-chat-streaming-errors` Chat calls, streaming and errors — messages, streaming, timeouts, rate limits, retries with backoff, idempotency
- `llm-apis-structured-outputs` Structured outputs — JSON schema, Pydantic models, validation and repair loops, confidence
- `llm-apis-tool-calling` Tool (function) calling — the tool-call loop, tool schemas, parallel calls, errors from tools; ToolCallDemo
- `llm-apis-documents-vision` Documents and images — PDF text vs scanned invoices, OCR vs vision models, layout variance
- `llm-apis-cost-caching-batching` Cost control — prompt caching concept, batching, smaller models for easy steps, token budgets
- `llm-apis-prompt-versioning-lab` Lab: a versioned extraction function — prompt files in Git, schema, retries, logging every call

**Interview questions:** How do you get reliable JSON from a model? · How does tool calling work? · How do you handle rate limits? · Azure OpenAI vs the provider's own API · How do you control cost per request?

## Phase 31 · `vector-db` — Embeddings and vector databases (Qdrant) · ★ core · 7 lessons

**Concept-first.** Meaning as geometry: similar text → nearby vectors; search = nearest neighbours.
**Setup.** Qdrant in Docker (local).

- `vector-db-embeddings` Embeddings — what they are, cosine vs dot product, dimensions, embedding models and their trade-offs
- `vector-db-chunking` Chunking — size and overlap, structure-aware chunking, metadata, chunking mistakes; RagSearch
- `vector-db-ann-concepts` Vector search internals — exact vs approximate, HNSW, recall vs latency, filters
- `vector-db-qdrant-setup` Qdrant setup — Docker, collections, points and payloads, REST and Python client
- `vector-db-qdrant-search` Searching with Qdrant — filters, payload indexes, scoring, updating and deleting
- `vector-db-hybrid-reranking` Hybrid search and reranking — BM25 + vectors, fusion, rerankers (concept)
- `vector-db-ops-pgvector` Operating a vector store — sizing, backups, updates, pgvector as the alternative

**Interview questions:** What is an embedding? · Cosine similarity · Why chunk, and how do you choose size? · HNSW in one minute · Hybrid search: why? · Qdrant vs pgvector.

## Phase 32 · `rag` — Retrieval-augmented generation · ★ core · 8 lessons

**Concept-first.** RAG = retrieval you can inspect + generation you can cite; the failure is usually retrieval, not the model.

- `rag-architecture` RAG architecture — ingest, retrieve, augment, generate; when RAG beats fine-tuning
- `rag-ingestion-pipeline` Ingestion — parsing PDFs, OCR, cleaning, metadata, idempotent re-indexing
- `rag-retrieval-citations` Retrieval and citations — top-k, thresholds, prompt assembly, "I don't know", source citations; RagSearch
- `rag-advanced-retrieval` Better retrieval — query rewriting, multi-query, parent-document, reranking
- `rag-evaluation` Evaluating RAG — recall@k, MRR, faithfulness, answer relevance, error analysis
- `rag-security-permissions` Security — document-level permissions, prompt injection through documents, leakage
- `rag-text-to-sql` Text-to-SQL agent over gold views — `run_readonly_sql`, allowed tables, row limits, refusal
- `rag-production-lab` Lab: policy RAG with citations — 10 synthetic accounting SOPs, Qdrant, FastAPI endpoint

**Interview questions:** Walk me through a RAG system · Why does RAG return wrong answers? · How do you evaluate retrieval separately from generation? · How do you enforce access control in RAG? · Chunking vs reranking: which first?

## Phase 33 · `evals` — Evals · ★ core · 5 lessons

**Concept-first.** If you cannot measure it you cannot change a prompt safely.

- `evals-concepts` Why evals — golden sets, offline vs online, regression testing for prompts
- `evals-metrics` Metrics — exact/field accuracy, semantic scoring, LLM-as-judge and its pitfalls, latency and cost per case
- `evals-datasets-regression` Datasets and regression — building a 50-case set, versioning, CI gates; EvalRunner
- `evals-tooling` Tooling — pytest-based evals and what the frameworks add ("check the current docs")
- `evals-human-review-lab` Lab: eval the invoice extractor — per-field accuracy across 50 invoices and a human-review queue

**Interview questions:** How do you know a prompt change made things better? · LLM-as-judge: risks · How big should an eval set be? · What do you track besides accuracy?

## Phase 34 · `guardrails` — Guardrails and AI security · ★ core · 6 lessons

**Concept-first.** Treat the model as untrusted input *and* untrusted output; safety lives in code, not in the prompt.

- `guardrails-threat-model` Threat model — OWASP Top 10 for LLM applications (concept), data flows, attack surfaces
- `guardrails-prompt-injection` Prompt injection — direct and indirect, defences that work and ones that don't
- `guardrails-pii` PII and data protection — detecting and masking PAN, IFSC, account numbers, emails, phones; logging safely; GuardrailTester
- `guardrails-sql-tool-safety` Safe tools — read-only access, allow-lists, limits, parameterised queries, confirmation for writes
- `guardrails-output-validation-hitl` Output validation and human-in-the-loop — schemas, business rules, confidence, review queues
- `guardrails-governance-lab` Governance and lab — policies, audit trail, responsible-AI checklist; lab: guard the Ask-Your-Finance-Data agent

### Project F · Invoice-to-Ledger AI + Ask-Your-Finance-Data (`proj-f`) + Gate F
Follows PDF Project 4, steps 1–6: 50 PDF invoices in 5 layouts (reportlab, some scanned-looking) → Pydantic `Invoice` extraction with validation (totals = lines + tax, GSTIN format, date sanity), low-confidence → human review queue, approved invoices load into the Project A database → Ask-Your-Finance-Data agent (tools: `run_readonly_sql` over gold views only, `get_variance(entity, month)`, `explain_kpi(name)`; guardrails: allowed tables, row limits, no writes, refuse out-of-scope) → RAG over 10 synthetic policy documents in Qdrant with citations and "I don't know" → evals: field accuracy on all 50 invoices, 50-question agent+RAG eval set (accuracy, latency, cost per question) → FastAPI endpoints + simple chat UI, Docker, README with results table, video.
**Interview questions:** Prompt injection: what are the real defences? · How do you stop an agent writing to your database? · How do you handle PII with a hosted model? · What is the human-in-the-loop design?
